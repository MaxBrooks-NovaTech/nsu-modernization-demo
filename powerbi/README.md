# Phase 5 — Power BI / PBIP

This directory contains both the source-controlled Power BI report specifications and a real native PBIP project for this demonstration.

## Contents

1. `executive-enrollment-admissions/`, `institutional-data-trust/`, `data-lineage-certification/` — `report-spec.yml` specifications for the three required report experiences (source models, semantic definitions, pages, visuals, slicers).
2. `NSU BI Modernization Demo/` — the native PBIP project (`.pbip` + `.Report` + `.SemanticModel`, TMDL format), built in Power BI Desktop on Windows since Power BI Desktop is unavailable on macOS.

## Data source: CSV, not a live PostgreSQL connection

The semantic model imports from the CSV snapshots in `seeds/mart_tables/` (generated by `scripts/export_mart_csvs.sh`), not a live PostgreSQL connection. This means the Power BI portion of the demo does **not** require Docker/PostgreSQL to be running.

**One manual step is required the first time this project is opened on a new machine**: the semantic model's `ProjectRoot` M parameter must be set to the local absolute path of this repository (e.g. `C:\Users\<you>\nsu-modernization-demo`). In Power BI Desktop: **Transform data → Manage Parameters → ProjectRoot**, set the value, then **Refresh**. This is a standard, portable Power Query pattern — it is the only environment-specific value in the model.

To refresh the CSV snapshots after re-running `dbt build` (e.g. after regenerating synthetic data):

```bash
POSTGRES_PORT=55432 bash scripts/export_mart_csvs.sh
python3 scripts/export_dashboard_reference_csvs.py
```

The second script regenerates the governance reference tables (`certification_catalog.csv`, `lineage_summary.csv`, `quality_test_evidence.csv`) used by the Institutional Data Trust and Data Lineage & Certification pages, from `certification/catalog.yml`, `docs/phase4/lineage.md`, and the actual last `dbt build`'s test results (`target/run_results.json`) — real evidence, not sample data. Then **Refresh** the semantic model in Power BI Desktop to pick up the updated CSVs.

## Governed metrics

The model's DAX measures (`Enrolled`, `Applications`, `Admits`, `Deposits`, `Yield`, `CensusEnrollment`, `IpedsEnrollment`) are written to match `semantic/metric_definitions.yml`'s `calculation` field for each metric exactly — not approximated with unfiltered row counts.

## Remaining manual Power BI Desktop step

The three report pages (`Executive Enrollment & Admissions`, `Institutional Data Trust`, `Data Lineage & Certification`) exist and are navigable, but their visuals (cards, charts, tables, slicers) still need to be built in Power BI Desktop per each `report-spec.yml`. This is GUI-authored work that cannot be done from a text edit — build it, then validate against the Phase 3 dbt marts and Phase 4 certification catalog before presenting.

See `PowerBIDashboard.md` (repository root) for the exact step-by-step checklist — opening the project, adding the dimension/reference tables, and what to build on each page.
